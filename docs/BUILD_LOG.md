## 2026-11-11 — Traces: Tracely's LLM-as-judge (evaluator columns)

- Ported Tracely's LLM-as-judge (commit `8c5c3d7`). An evaluator is a column on the Traces table at conversation, message or step level. Backend in `lib/judge/` (TypeScript ports of Tracely's Python): `llm-judge.ts` (level dispatch, output types score / number / boolean / text / json, sequential mode, `depends_on`, context gate with a fallback model), `decision.ts` (decision-model columns: binary, multi-class, multi-label, and the LLM fallback that answers the same question), `template.ts` (`@VARIABLE` templates), `conditions.ts` (`run_if`), `prompts.ts` and `text.ts` (what the judge reads), `budget.ts`, `generation.ts` ("Use AI"), `catalog.ts` (the 18 LLM-judge templates, generated from Tracely's catalog), `service.ts` (trace and thread runs), `store.ts` (evaluators, scores, validation).
- `provider.ts` calls OpenRouter with `fetch` (Tracely drives LangChain): `/chat/completions` with the reply's JSON Schema as `response_format`, the Decisions API for decision models (TypeSafe Jev), and the model list. A model or provider without native structured output gets the schema in the prompt and the reply is parsed, so any chat model id works; the editor's model picker also takes a typed id. Setting names follow Tracely (`OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`, `LLM_JUDGE_MODEL`, `COLUMN_DEFAULT_MODEL`); a custom base URL moves the Decisions URL with it.
- The key is one private file (`<data>/openrouter.key`, mode 600) set from **Traces → Evaluators**, or the environment. It is not in SQLite and not in exports. With no key no request leaves the machine (the model list is then static). A run sends the judged trace content and the rubric to OpenRouter.
- Storage: two new tables, `evaluators` and `eval_scores`, created with `IF NOT EXISTS`; exports include them. A score's id is its address (trace, column, span; or thread, column), so a re-run replaces it; a column's run retracts the scores it no longer produces; deleting a column or changing its level removes its scores. The judge's calls (prompt and answer) are stored on the score, and the cell's "LLM prompt & answer" reads them (Tracely reads them from a trace it records about its own work). Cost is the sum of what the provider reported; Tracely's price table is not ported.
- API: `/api/evaluators` (+ `[id]`, `models`, `templates`, `cost`, `resolve`, `generate`), `POST /api/evaluations/run` (server-sent events, 3 targets at a time), `GET /api/evaluations/prompt`, `/api/llm-key`. The trace and session reads carry scores and a roll-up verdict (FAIL when a non-advisory column failed).

## 2026-11-12 — Knowledge graph: cards, a layout that follows the links, focus

- Problem (from a 51-record, 98-connection workspace): the graph could not be read. Records sat on a fixed spiral in list order, so links crossed everywhere; every record always showed a title and a type label; the text was inside the scaled SVG, so it shrank with the zoom and with the canvas (about 5 px at 55%); tasks and experiments had the same colour, and so did notes and manuscripts; a pair linked by a relation and by a reference was drawn and counted twice; most records were tasks.
- `lib/graph.ts` (new, pure, deterministic, no new dependency):
  - `graphEdges`: typed relations first; a chart link, a shared file or a `linkedIds` reference adds an edge only when the pair has none. `graphLines`: one line per pair (strongest type, directions).
  - `cardSize`: the box of a record's card from its title (1 to 3 lines, at most 168 px wide). The view sets the same width and height on the element.
  - `layoutGraph`: each group of linked records gets a force layout written here (links pull, records push each other away, a pull to the centre); x is stretched because cards are wide, then cards that overlap move apart (22 px and 20 px of free room). Groups sit side by side, the largest first. Records with no link go in a grid under them.
  - `placeCards` (which records are cards when the zoom leaves no room for all; the rest are dots) and `placeLabels` (a title next to a dot, on the first free of 8 sides, never on a card, a dot or another title, never outside the visible area).
- `components/knowledge-graph.tsx` (new; the component left `components/views.tsx`) and `app/graph.css` (new; the old `.graph-*` rules left `app/globals.css`):
  - A record is one HTML button: a card (type icon, type colour on the left edge, full title) or a dot. Lines are curved SVG paths under the cards. A card follows the zoom from 80% to 100% and keeps its size outside that range; titles next to dots are always 11 px.
  - Tasks start hidden when the workspace has other record types. The type row is the legend and the filter, and the counter says "19 of 55 entries".
  - Hover or select a record: it and its neighbours become cards with arrow heads, the rest fades. The search does the same for the matches; Enter selects the first one.
  - Pinch or Ctrl/⌘ + scroll zooms at the pointer (a plain scroll still scrolls the page), drag moves, the fit button and the first view show the whole graph (not under 40%).
  - The side panel lists the most connected records, or the selected record with its connections (direction, type, or the origin of an implied edge).
- Design choices (mine, not requested in detail): tasks are grey and hidden at first; decorative text and the "persistent memory" corner label are gone.
- Measured on a synthetic fixture (51 records, 98 lines: 33 tasks, 3 hub journals with random links, plus the 4 records of a new store), written through the HTTP API into a throwaway store at 127.0.0.1:3311 (webpack dev server), 1440×900 window, 819×553 canvas:
  - Tasks hidden (19 records, 18 lines): fit at 86%, 19 cards, 0 dots, 0 card overlaps, 0 titles cut inside a card, 0 cards cut by the canvas edge.
  - Tasks shown (55 records, 98 lines): fit at 52%, 14 cards, 41 dots, 17 dot titles, 0 overlaps. At 82% and above: 55 cards, 0 overlaps.
  - Layout time for the 51 records: 8 ms.
- Verification run: 10 tests in `tests/graph.test.ts` passed. Browser QA on that store: hover, select, drag, click on the empty canvas, zoom buttons, Ctrl + wheel, the fit button, search with Enter, the panel lists, showing and hiding tasks; Moss and Paper; 375 px wide (no horizontal page overflow, fit at 41% with 5 cards and 14 dots); no console errors from the page. The real store on port 3000 was not used.
